## Staging 有而 Production 没有

本轮确认两环境的backend/frontend镜像一致、Flyway ledger一致；不能声称“Staging独有新源码功能”。已确认差异是**运行配置**：Uber global enabled在Staging=true、Production=false；两个数据库/Store/device/credential universe独立，本轮没有读取业务数据进行对比。Staging历史sandbox mappings/physical QA不证明Production merchant已开启或所有Pad兼容。其他数据、module enable、feature有效值和APK差异保持UNKNOWN。

## 关键回归缺口

在不改现业务的前提下，后续计划应补足：跨Organization的REST/WS/profile访问负向矩阵；不同菜系/任意工位/套餐/无堂食的打印golden snapshots；库存并发与BOM scope；same bundled origin切换环境时的pending outbox/credentials；多税/币种/时区的有效期快照；空库不导入Lan Zhou数据；版本升级/数据导出/隔离restore；被支持APK/硬件的实际矩阵。

没有运行这些测试不代表全部失败；没有覆盖率报告时不得声称百分比。当前70 unit PASS及异常修正过程见02；它们证明既有fixture的有限回归。
